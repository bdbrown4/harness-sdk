# SSH and Docker environments

`Strands.Agents.Sandbox.SshSandbox` and `DockerSandbox` start the selected native client for each command. The application fixes the destination, credentials, user, executable, and local process limits. Command input can change the target working directory and POSIX environment; it cannot replace the selected transport. These clients do not provide local OS isolation. They use the installed OpenSSH or Docker client and its application environment and configuration.

Wrap a core environment in `new Strands.Harness.SandboxAdapter(selected)` to supply `HarnessOptions.Sandbox`. A raw managed `sandbox` module export can also return a core `Sandbox`; configuration binding adapts it. Explicit `SandboxResolver` remains authoritative. Commands, environment discovery, skills, text tools, and binary memory/storage access use that selected backend. The adapter never substitutes host files or commands.

SSH matches the pinned Python/TypeScript allowlist, uses `BatchMode=yes`, and defaults to `StrictHostKeyChecking=accept-new`. `AllowUnknownHosts` explicitly selects `no`; `AllowUnsafeSshOptions` permits options excluded by the upstream allowlist and may grant local client authority. Keys, known-hosts files, and trust policy belong to the application. Docker targets an existing container and places `--` before its name; omitted user and directory defer to container configuration. Neither client creates a daemon, container, SSH service, or credential store.

The target requires a POSIX shell and the utilities `base64`, `mkdir`, `mktemp`, `cp`, `mv`, `rm`, and `wc`. Binary files travel as base64 through bounded client capture and owned stdin. A truncated or malformed response fails instead of returning partial file bytes. Writes validate the decoded length before replacing a sibling temporary file, reject terminal symbolic links, and preserve an existing file's metadata through `cp -p`; a new file starts with `mktemp` permissions. NUL-framed directory listings retain newline names and symbolic-link metadata. The shared `FileEntry` contract rejects names containing backslashes. Text decoding uses strict UTF-8 and byte reads retain a BOM. Missing deletes are a no-op, matching the native `IFileSystem` contract; upstream `removeFile` reports a missing path as an error.

`SandboxProcessOptions` adds native application limits: a combined 32 MiB capture cap, optional hard deadline, and bounded cleanup. Each call can request smaller limits. Excess command output is drained and marked truncated. Nonzero exits are ordinary results. Timeout and cancellation retain partial output. Modern assets use the platform process-tree termination API; the Standard asset supports native clients on Windows and terminates the owned client process. Stopping a local client does not guarantee termination of remote commands or already orphaned descendants. Deferred cleanup is observable through a nonfaulting `Task<IReadOnlyList<Exception>>` at `Exception.Data["Strands.CleanupTask"]`; diagnostics are process-local, without a binary serialization contract.

The separate POSIX curl transport also needs `awk`, `head`, `mkfifo`, `sed`, and a temporary filesystem supporting named pipes. A Windows-mounted WSL temporary directory can reject `mkfifo`; select a POSIX-capable temporary directory inside that selected environment. No automatic host HTTP fallback occurs.

This slice does not add upstream sandbox-vended tool factories, interpreter execution helpers, background task/session lifecycle, or a remote security boundary. Protocol fixtures verify argv and process invariants; the recorded loopback OpenSSH and task-owned Docker daemon checks are separate evidence, not certification of arbitrary servers or containers.
