# Optional persistent Bash

`Bash.Create(BashConfig)` creates an application-owned `IRichTool` with one independent persistent interpreter association for each borrowed `Agent`. Add it explicitly to the agent's tools and dispose the tool when its application lifetime ends. An agent's shutdown closes its association; shutting down one agent does not close another agent's session. No default Harness tool is replaced.

The input has `mode: "execute"` with a nonempty `command`, or `mode: "restart"`. Execute returns structured `{output,error}` after both stream fences. An ordinary nonzero shell status is not an SDK exception and does not add an exit-code field. Whitespace-only commands are valid. The optional positive finite `timeout` is in seconds; the first execution timeout becomes that association's default. Restart returns `Bash session restarted`, discards the old interpreter state and resets that default to 120 seconds. Creation and restart are lazy: execution starts the interpreter.

The configuration copies environment overrides and captures the initial working directory when the tool is created. The default combined UTF8 output bound is one MiB and cleanup bound is five seconds. `PS1` and `PS2` are empty in the child. Select an absolute compatible interpreter path when deployment cannot rely on `PATH`. The tool uses the existing SDK binary child-process owner, no-BOM stdin, independent stdout/stderr fences and bounded byte collection. Output trimming follows the pinned JavaScript whitespace set. Bash commands provide full host execution authority; this tool provides no execution isolation.

Calls for one agent serialize. Caller and context cancellation stop the active generation, physically join its owned process and pipe work, and preserve the applicable original cancellation token. A canceled queued call does not cancel the active call. Restart cuts off admitted commands belonging to the old generation. Timeout retains observed partial output on the exception's `Strands.Bash.StandardOutput` and `Strands.Bash.StandardError` data entries. Cleanup failure is reported; a bounded failure is not a claim that physical cleanup succeeded. The caller owns cancellation sources. Borrowed agents and tools retain their declared lifetimes.

This is a native implementation of the pinned TypeScript optional persistent Bash behavior. Python's deprecated stateless shell interface is a separate boundary. Native process ownership, lazy restart, stronger stream framing and output bounds are explicit native choices. Unix descendant-group cleanup and arbitrary user reconfiguration of shell descriptors, prompts, traps or background writers are not isolation guarantees.

## Conformance

The 53 focused Bash cases require an explicitly selected `STRANDS_BASH_TEST_EXECUTABLE` on an owned runner. The reviewed component passed on Windows and Linux with .NET 8 and .NET 10, and on genuine .NET Framework 4.8 in x64 and x86. The six-profile matrix passed 326 checks, including shutdown registration and pointer-size controls. The final source differs from the executed source only in two independently verified import/whitespace changes. See the SDK validation results for retained failures, source bindings and package qualifications.

The cases cover validation, detached configuration, two-stream framing, UTF8 one-byte writes, trimming, bounds, file-gated serialization/cancellation/restart, per-agent lifecycle, malformed startup and physical interpreter exit. Separate writes do not assert operating-system read segmentation. Process fixtures retain an independent handle for each SDK-owned interpreter and release their gates, dispose owned resources and join admitted calls on failure. No universal descendant containment guarantee follows from these cases.

The focused component uses serialized execution. Full current-composition, default parallel and macOS verification remain required. Core and Harness managed packages pass normal three-target API validation; fresh complete Harness NuGet consumption remains open pending the full legitimate native dependency feed. The tool is optional and does not run unless explicitly registered and invoked.

## Focused acceptance qualifications

The first-timeout persistence case intentionally times out its first explicit 0.15-second command, then requires the next command with no explicit timeout to retain that default; restart must reset it to 120 seconds. It does not require a cold interpreter to finish a `printf` within 150ms. The native execution deadline includes `Generation.Start`; pinned TypeScript calls its synchronous `start()` before installing the timer, without an interpreter-ready handshake. This timing-boundary difference is explicit: the test correction does not establish exact startup-timer parity or explain the earlier unclassified process-exit observation. The original Framework x86 cold-first-command failure remains retained.

The partial-output timeout contract copies only the documented stdout/stderr strings through the native exception wrappers. The final conformance case first completes a `:` command and both stream fences before its unchanged 1.5-second deadline; the original cold-start failure is retained separately. This does not move the runtime deadline or promise partial bytes before the interpreter emits them.

Process tests bind the current Agent association's SDK-owned root with a separate retained OS process handle. The idle-exit case deliberately terminates only that owned root, requires physical exit, and immediately issues a fresh command. Shell `$$` and same-image enumeration do not establish Windows root ownership. The explicit-exit case asserts the owned root immediately and retains all same-image observations in its test output. The two-agent tool-disposal case immediately asserts both separately retained SDK-owned roots and then joins the accepted calls; every same-image observation is retained diagnostically, without inferring ancestry or job ownership from its image path. Its earlier all-observed immediate-exit failure remains unclassified because the failing PID/root-versus-helper role was not captured. Active caller cancellation, actual added-agent context cancellation, restart and agent shutdown likewise bind their exact SDK association root before the boundary, require advisory-set membership, and immediately assert only its separately retained OS handle after the public completion; all same-image observations remain diagnostic and fixture-owned views are still disposed during cleanup. The advisory set does not establish ancestry or job ownership. Accepted-call token/status/drain checks and the VM driver's separate zero-private-interpreter-process closure remain unchanged. Earlier all-image assertion failures stay retained without an inferred failing-PID role or operating-system cause. Public shutdown joins owned operations/resources; arbitrary enclosing async test wrappers are joined within their existing bound after the immediate physical assertion.

Earlier Windows/Linux failures and diagnostic comparisons remain retained, including the unclassified original Windows explicit-exit observation. The later genuine Framework4.8 component runs include actual x64/x86 pointer assertions; registry presence during a modern .NET run alone would not establish Framework execution.
