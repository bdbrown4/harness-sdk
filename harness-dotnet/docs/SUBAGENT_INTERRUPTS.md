# Subagent streams and human input

The Harness delegation tool implements `IStreamingTool` and `IRichTool`. Its existing `Create` return type and authority-derived task schema stay the same. Nonfinal child events are forwarded once as tool stream data; the child result becomes one terminal tool result. The terminal text and error policy retains the pinned Harness behavior: cancellation, filtering, refusal and exhausted turn/token budgets report an error with any partial output.

A child human-input request pauses the parent instead of becoming an ordinary tool result. The parent uses the existing native agent-tool interrupt journal to store a detached child session checkpoint before the owned child is disposed. Resuming builds one fresh child, validates the granted tools and named MCP servers, restores the turn and forwards answers to its exact pending call IDs. Real FileSessionStore recovery can reconstruct both parent and child; completed sibling calls are not repeated. Partial answers and later pauses retain their existing correlation. The parent's original invocation-state dictionary and application values are preserved.

Context `all` already contains the framed task in its prepared history and uses a null first prompt. This internal path therefore accepts a nullable first prompt rather than pretending the public typed `AsTool` input schema has a task field. Current depth authority is reapplied after restore by a scoped BeforeInvocation hook, before new model/tool execution. That hook is removed before child disposal. A restored checkpoint cannot increase a reduced parent depth.

The Harness owns the fresh child and its iterator; the internal core adapter borrows that child. Pause, completion, cancellation and early consumer closure dispose the child and release its provider consumers. Borrowed models, filesystems, provider objects and caller HTTP clients retain their normal ownership contracts. When child execution and cleanup both fail, the original error or requested cancellation stays primary, with cleanup diagnostics attached. Reusing the same exception as a cleanup error does not attach it to itself. Ordinary error results retain their local Error cause; that diagnostic is omitted from serialized/provider payloads.

Direct tool calls continue to refuse human interruptions, even if an after hook attempts to replace the result. Background delegations route questions through their owning task. Early parent stream closure runs no hidden child continuation. No generic tool refresh or mutable authority API is added.

The pinned upstream is monorepo commit `3bd98e618320f0f286acbfb2252f72388030421b`: Python `harness-py/src/strands_harness/tools/subagent.py:470–582` and TypeScript `harness-ts/src/tools/subagent.ts:582–712`. Both stream nonfinal events, retain paused children by tool-use ID and forward human answers on resume. They retain live child objects in memory. Native Harness instead reuses its durable detached journal and closes owned children on pause; this is a deliberate stronger restart contract, rather than a claim about upstream process persistence. Python copies its invocation-state dictionary because its SDK rewrites an agent entry; native ToolContext carries the child separately and does not rewrite caller values.

Public `Agent.AsTool` overloads retain their existing schema, reset/preserve, delegation and borrowed-agent behavior. The internal fresh-child adapter does not construct or dispose an extra agent. This component does not establish live external MCP service, fresh package, macOS, or clean Framework execution proof by itself; validation receipts identify the actual tested source and host.
