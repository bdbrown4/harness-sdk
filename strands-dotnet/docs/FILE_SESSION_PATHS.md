# FileSessionStore paths

`FileSessionStore` resolves its application-selected root with `Path.GetFullPath` when constructed. On Windows it then uses an extended absolute path (`\\?\` for a drive path, or `\\?\UNC\` for a UNC path). An already extended root is retained. This addresses the legacy Framework path-length limit without changing process switches, registry settings, current directory, or generic storage backends. On other operating systems the resolved path is unchanged.

Relative roots and parent segments resolve before the Windows prefix is added. Unicode directory names and payloads retain their native encoding. Session IDs remain opaque: the lowercase SHA256 filename has not changed, and path-shaped IDs cannot select a filesystem location. Existing snapshot JSON, validation, missing-session behavior, temporary-file cleanup and replacement operations are unchanged. Filesystem permissions, reparse-point behavior, component length limits and share availability remain those of the existing backend. The UNC transformation is reviewed code; this increment does not include a live network-share test.

The exact3441cab source reproduced two distinct failures on local Framework4.8.1, running the net48 target in both x64 and x86 processes. A217-character directory created its254-character temporary file, then `File.Move` failed at the287-character hashed destination. A300-character directory failed during `Directory.CreateDirectory`. A direct operation test demonstrated that extended paths reach and move the same physical bytes. The original tests retain both directory lengths and successful roundtrip/replacement assertions after the fix. Raw failing TRX and source are retained separately from green evidence.

Coverage also includes normal and Unicode roots, relative roots with parent segments, already extended paths, opaque IDs, existing JSON, cancellation, validation failure, blocked publication, temporary cleanup, independent-key concurrency and shared-session saves under an application lease. Long-path operations leave the process path switches unchanged. Actual Framework architecture assertions accompany final execution evidence. Local net48 proof uses installed Framework4.8.1; it is not a clean4.8 or fresh Linux claim.

The existing save algorithm still requires an application-level lease when a session is shared. During this increment,24 simultaneous **unleased** same-session writes produced a `File.Replace` IOException. That failed assertion and test body remain a separately identified characterization; they have not become a passing concurrency guarantee. The new leased test has a distinct name. This path fix adds no retry, global lock, transaction, or atomic-replacement redesign.

This is a portability repair for the native whole-snapshot store. It does not change the separate indexed repository, Agent cancellation, sessions, managers, or upstream wire formats.
