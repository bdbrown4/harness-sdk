# Ordinary-Agent snapshot catalog

`SnapshotSessionManager` is an optional `IPlugin` over borrowed `IStorage`. It stores complete native latest records and immutable UUIDv7 checkpoints. `SaveSnapshotAsync(agent, false)` returns an immutable handle without changing latest; `true` replaces latest. `ListSnapshotIdsAsync` lists immutable handles oldest first with an exclusive cursor. `RestoreSnapshotAsync` selects a handle or latest. Existing two-method `ISessionStore` implementers and the original two-argument manager constructor remain supported.

Reopening a scope requires an explicitly stable `AgentOptions.Id`. Default agents and children retain their distinct generated IDs. Catalog identities use the native Bidi single-segment ASCII profile; old opaque file-session and repository IDs are unchanged. The native envelope binds version, session, agent, handle and model profile. It is not a TS/Python JSON interchange format.

Save and restore hold an exclusive inactive Agent reservation across actual stash/backend I/O. Direct tools, invocation, classic reduction, manual snapshot mutation, tool publication and terminal lifecycle cannot cross it. Only the private owning operation may initialize with an already prepared selected snapshot. Fresh selected restore applies before plugins and `Initialized` observers; initialized rewind reruns neither initialization nor model/tool bodies. Every malformed snapshot field is prepared and validated before stash or live writes.

At the initialized-restore cutover, receipt, background and token checks occur under the admission monitor. The nonawaited prepared commit follows outside that monitor while the reservation remains held. Deferred provider updates publish at release. Custom classic actions and checkpoint getters run outside the Agent monitor. A custom action can throw after its own side effects; arbitrary plugin code has no rollback guarantee. Existing custom-manager contracts still require preparation without mutation and nonthrowing atomic assignment.

Default and agentic context presets, empty pipelines and immutable built-in Offload/Emergency strategies support initialized restore. Custom `ContextStrategy` mutable state has no serialized restore contract and is rejected specifically for initialized rewind; its initial selected restore remains supported. Inline originals are validated and merged through the configured stash failure policy. A valid backend failure can leave a partial merge, and initialization can fail after valid native state was applied. External stash type markers are diagnostic and never authorize opening another backend.

The default automatic strategy is `Invocation`, which saves after completion hooks. `Message` also saves after each completed accepted `MessageAdded` dispatch. Native input admission remains atomic for a multi-message batch, so each event checkpoint contains that accepted batch. `Trigger` suppresses ordinary automatic writes unless the predicate succeeds or fails. A true predicate captures once and writes immutable before latest; a failed predicate skips immutable and falls back to latest even if logging fails. Redaction forces a real latest write in every strategy. Suppressed or failed writes never advance the saved frontier. Standalone interrupt-abort writes retain native durability after their message hooks.

These policies deliberately select the pinned Python profile. Pinned TS saves latest before evaluating its trigger, propagates trigger errors, performs the successful pair concurrently and omits the Trigger redaction hook. The native ordered pair is not a multi-key transaction: latest failure can leave an orphan immutable record, and retry performs real writes.

`DeleteSessionAsync` deletes all catalog records in the selected session, including records for agents no longer bound. It reserves every currently bound Agent before listing and blocks new bindings until physical completion. Complete listings are detached and every nonempty canonical exact-prefix descendant is validated before deletion; duplicate keys are deleted once. Other sessions and caller-selected namespaces are retained. Backend failures can leave a partially deleted session. Live history, state, cursor and bindings are not cleared; a later accepted operation may recreate latest.

Known automatically scoped context stashes use `ClearSessionAsync`; explicitly caller-scoped shared roots remain untouched. If no bound Agent has a known stash, deletion uses only the exact constructor-supplied backend to clear that session's context prefix. This follows Python's same-backend assumption; it cannot discover originals on a separately configured backend. A known caller-scoped stash suppresses fallback. Pinned TS has no unbound fallback. Ordinary stash-cleanup failures are diagnostic after catalog deletion, while cancellation exceptions propagate.

Stash session deletion validates and detaches its entire listing before destructive callbacks. Existing opaque stash identities remain valid. Completed `.` segments retain the file backend's physical alias behavior; custom/memory stores can retain literal dot segments. This is not a promise that physically aliased file roots represent distinct logical sessions. The stricter catalog identity rules are unchanged.

Caller cancellation is checked before admission and subsequent destructive operations. Started I/O is physically awaited before reservations release, and independent backend failures keep their causal identity. A successful last accepted stash delete is not falsely reported as uncommitted when cancellation races its return. Invocation completion checkpoints use the existing noncancelable cleanup token. There is no cross-instance writer exclusion, external transaction, arbitrary application mutation, remote-provider rollback or ownership transfer. Storage and supplied loggers remain borrowed.

Memory retrieval is computed per request. Extraction has separate accepted-message buffers and confirmed external writes; rewind does not undo that work or reset custom extraction-trigger counters. Restoring history emits no `MessageAdded`, so restored messages are not extracted again. This matches the pinned TS/Python boundary and does not imply rollback of external memory facts.

This component's deterministic catalog, storage, hook and lifecycle tests do not execute interpreters, console profiles or external services. Package, portable and composed integration acceptance is recorded separately from source-level and selected runtime evidence.
