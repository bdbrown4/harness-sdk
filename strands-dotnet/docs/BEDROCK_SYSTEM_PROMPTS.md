# Structured ordinary system prompts

Ordinary system prompts use optional `ModelRequest.SystemPromptContent` with the existing native text, cache-point and guard-content blocks. Its default is null. The existing three-argument request constructor, string-only behavior and default JSON shape remain the compatibility boundary. Typed content supplies an ordered system list and a newline-joined plain-text projection; explicit typed presence takes precedence over a simultaneously supplied legacy string.

The accepted typed list is detached before transport awaits. Bedrock preserves caller order and every nonempty caller checkpoint TTL. Managed system caching does not append a duplicate when a caller point exists. The explicit cache profile may fill a missing TTL using its system section and existing tools standdown rule. Legacy string cache behavior remains unchanged. Explicit empty typed content and legacy empty strings have separate presence semantics.

The Agent propagation stage adds `AgentOptions.SystemPromptContent` and the read-only `Agent.SystemPromptContent` view. Configure either the legacy string or typed content; two nonnull values are rejected, including empty strings and empty lists. Options detach list membership before Agent construction. Default children inherit the current accepted representation, including a restored prompt, while continuing to borrow their model and other dependencies. A child configuration that switches to a string must explicitly clear the inherited typed option.

Model middleware has an explicit whole-prompt replacement rule. Assigning `InvokeModelContext.SystemPrompt` clears typed content even when the string equals its text projection or is null. Assigning `InvokeModelContext.SystemPromptContent`, including null, replaces both representation and projection. The last explicit initializer wins. This differs deliberately from the `ModelRequest` typed-precedence rule described below; a `BeforeModelCallEvent` hook that edits its request must still explicitly clear typed content when switching to a string.

The existing snapshot `systemPrompt` key can contain a typed array as well as its earlier string/null forms. Absence preserves the current prompt; a present string or null clears the typed representation. Typed arrays are fully validated and detached before initialization. Existing `SessionSnapshot.HasSystemPrompt`, `SystemPrompt`, and `SystemPromptContent` retain their matching-projection contract, without a new session key or schema. Ordinary saves, catalog captures, abort writes, goal rewind, and Agent-tool reset baselines retain ordered typed membership before downstream awaits.

Skills append one XML text block to a typed request while preserving caller checkpoints and order. This does not mutate the Agent's accepted prompt, and repeated calls do not accumulate XML there. The legacy string branch retains its double-newline separator. Providers without typed checkpoint support continue to consume the matching plain-text projection. Local token estimates use that text projection and additionally count selected guard text with the existing per-block text heuristic; cache markers and guard images add zero. Native counting and telemetry remain subject to their existing provider and privacy policies.

The ordinary system union accepts the existing immutable `GuardContentBlock`, preserving selected text or inline PNG/JPEG image bytes and qualifier order, including duplicates. The Bedrock mapper reuses its existing message-guard mapper and per-request owned image streams for ConverseStream, Converse and native CountTokens. The original one-argument/no-argument internal session-copy methods retain their text/cache contract and CLR signatures; ordinary hosts and neutral storage opt in through explicit guard-enabled overloads. Bidi continues to reject system guards before connection or accepted-state replacement, including an ordinary guard prompt loaded from neutral file storage. This does not add Bidi guard support.

Official signed loopback tests establish local request projection only. Final cross-target/API/package and genuine Framework 4.8 integration evidence are separate acceptance boundaries.

The new property retains immutable block values in a detached, read-only membership list. A `with` expression that switches back to the legacy string representation must also set `SystemPromptContent = null`; otherwise the accepted typed representation still takes precedence. Empty typed membership omits the Bedrock system field. Only text blocks contribute to the newline-joined plain-text projection. Unsupported content variants are rejected before official client I/O. Guard-only typed content has a null plain-text projection. Providers using only the matching plain-text projection do not receive selective guard semantics.
