# Experimental MCP task execution

Native task support selects between finalized SEP-2663 (`2026-07-28`) and legacy tasks (`2025-11-25`) from the negotiated protocol and server capabilities. `McpTasksProtocolProfile.Negotiated` is the default when tasks are enabled. This changes the earlier finalized-only default in the unpublished alpha; the numeric values and behavior of explicit `Finalized20260728` and `Legacy20251125` remain available. All profiles use the existing official `ModelContextProtocol.Core` 2.2.0 client for transport, protocol negotiation, request correlation, notification delivery, and cancellation. They do not introduce another JSON-RPC session or task scheduler.

Task support is opt-in. Existing `CreateAsync`, `CreateHttpAsync`, and `CreateStdioAsync` overloads retain ordinary tool-call behavior. The additive settings-first overloads accept `McpClientSettings { TasksConfig = new McpTasksConfig() }`. HTTP clients remain borrowed; disposing the native client closes its owned protocol connection. Stdio connections own their started process through the official transport.

```csharp
await using var client = await McpClient.CreateHttpAsync(
    new McpClientSettings { TasksConfig = new() },
    httpClient,
    new HttpClientTransportOptions
    {
        Endpoint = new Uri("https://example.test/mcp"),
        TransportMode = HttpTransportMode.StreamableHttp
    });

var tools = await client.ListToolsAsync();
var result = await client.CallToolAsync("lookup", arguments, cancellationToken: token);
```

Automatic calls return direct results immediately or poll a server-created task until completion. Completed `isError` tool results remain ordinary tool errors. A failed task throws `McpTaskFailedException` with its JSON-RPC code and detached details. A server-cancelled task throws `McpTaskCancelledException`; caller cancellation retains the caller token, and native deadline expiration throws `TimeoutException`.

The explicit lifecycle methods require a negotiated `2026-07-28` session and its advertised task extension, under either `Negotiated` or `Finalized20260728`. The legacy-only profile rejects these finalized operations. `SubmitToolAsync` invokes exactly once and never polls a task handle. `GetTaskAsync` returns an immutable validated state and checks the requested task identifier. `UpdateTaskAsync` accepts a response map, and `CancelTaskAsync` requests cooperative cancellation. Cancellation acknowledgement does not guarantee that remote work has stopped. No task state is written to the caller's agent invocation state.

`McpTasksConfig` uses `TimeSpan`: five minutes for the complete automatic operation, one minute for request inactivity, and one second for a missing server poll cadence. Progress resets request inactivity but cannot extend the automatic deadline. Explicit get/update/cancel operations retain a fixed one-minute request budget by default, including progress. Server cadence is clamped to at least ten milliseconds and timer-safe maximum waits. Native timer settings must be positive and no greater than `Int32.MaxValue` milliseconds.

Task states require nonempty IDs, known statuses, ISO timestamps with UTC offsets, chronological updates, and a present nonnegative integer `ttlMs` or explicit null. Complete states require exactly the payload belonging to their status. Every embedded input request is detached and validated before any input handler runs. Automatic polling uses the official client's configured handlers, deduplicates accepted input keys, validates the complete response batch, and only then sends the update. A missing or failed handler ends the operation and attempts cooperative cancellation. An uncooperative application handler can continue its own work after cancellation; the native wait is bounded, late faults are observed, and no late update is sent.

Sampling messages use the task extension's explicit user/assistant and content unions; accepting the general official content DTO alone would admit malformed input or content types that sampling forbids. Form elicitations must also be representable by the official .NET handler's restricted object-schema DTO, and URL elicitations require an absolute URI. The pinned task extension itself accepts a generic JSON object for `requestedSchema` and a string URL; these native handler constraints are stricter and are not a claim that its schema deeply validates form properties. Native task metadata additionally rejects negative durations and nonchronological timestamps instead of treating those values as opaque strings or integers.

Task routing uses the official message-context routing name. Non-ASCII, surrounding whitespace, and base64-sentinel-looking task identifiers receive the source-defined base64 header encoding. The official client supplies ordinary `Mcp-Method` and tool-schema parameter headers. Protocol framing and rich results remain owned by the official client and native MCP adapter.

Harness server maps accept `tasksConfig` in milliseconds: `pollTimeout`, `requestTimeout`, and `pollInterval`. The deprecated `ttl` alias is used only when `requestTimeout` is absent, matching the TypeScript loader. Typed server maps accept `McpServerOptions.TasksConfig`. Environment expansion, failure policy, connection ownership, tool prefixes and delegated server authority retain their existing contracts.

Negotiated automatic execution selects finalized tasks only with protocol `2026-07-28` and an object-valued `io.modelcontextprotocol/tasks` extension. It selects legacy tasks only with the exact `2025-11-25` revision, server `tasks.requests.tools.call` capability, and tool `execution.taskSupport` of `optional` or `required`. Capabilities from one generation cannot authorize another. Missing capabilities, other revisions, and forbidden legacy tools use an ordinary call bounded by both request inactivity and the complete operation deadline. Explicit profiles keep their earlier generation-specific selection; the finalized-only profile's ordinary fallback retains the ordinary client contract.

Legacy discovery is cached only after its bounded attempt settles; aborted discovery remains retryable. Task-backed calls submit `task: {}`, poll `tasks/get` while working, and obtain `tasks/result` after completion or an input-required transition. Input-required result waits use the remaining overall operation budget rather than ordinary request inactivity, allowing the official session to dispatch queued elicitation. Legacy failed status throws `McpLegacyTaskFailedException`, preserving status text without inventing a JSON-RPC code. Cancellation is attempted only when the task is nonterminal and the server advertises cancellation.

`LegacyTimeToLive` is an explicit positive whole-millisecond server retention request. Null omits wire TTL, matching TypeScript; Python callers can explicitly choose their desired retention period. Native JSON binding accepts `protocolProfile: "negotiated"` (also the omitted default), `"legacy2025-11-25"`, or `"finalized2026-07-28"`, plus `legacyTtl`. The retention setting is allowed in negotiated and legacy profiles and sent only when legacy task execution is selected. It is omitted for finalized execution and ordinary fallback. `legacyTtl` is separate from the deprecated `ttl` request-timeout alias. Retention does not extend local deadlines and remains rejected on the finalized-only profile.

Official .NET 2.2 omits legacy task capabilities from its typed `ServerCapabilities`. Negotiated and legacy profiles therefore observe the single raw initialize response before conversion and retain only the task/cancellation capability flags. The official client performs its existing discover-to-initialize fallback; the native adapter does not reconnect or start another negotiation. Its transport wrapper forwards the original reader, messages, session identifier, cancellation, and disposal; it owns no second receive queue or request registry. The official client's internal transport-kind diagnostic consequently reports `unknown` for that wrapper instead of its concrete `tcp` or `pipe` label.

The pinned sources differ materially. TypeScript selects between finalized and legacy execution from negotiated capabilities when tasks are enabled; native negotiated selection follows that default. The Python SDK supports `mcp>=1.23.0,<2.2` and feature-probes both runtime lines: MCP 1.x uses legacy tasks, while MCP 2.x supports finalized lifecycle methods with the required negotiated protocol and extension. The Python harness explicitly rejects `tasksConfig`; its development and integration extras pin `mcp<2` for their FastMCP test fixtures. Native explicit profiles allow applications to retain generation-specific behavior. Notification-assisted settling, per-call timeout overrides, declarative client-credentials authentication and the separate lazy MCP router remain subsequent parity work. No foreign runtime or authorization-code substitution is used.
