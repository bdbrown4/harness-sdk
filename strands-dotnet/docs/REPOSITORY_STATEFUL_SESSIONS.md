# Stateful indexed Agent sessions

`RepositorySessionManager` can bind a native `IStatefulModel` without changing its constructor or the public repository interface. The provider and repository remain borrowed. Stateful model configuration still excludes classic and first-class context reduction under the existing Agent contract.

Every accepted local message receives a numeric archive row through the existing append receipt. Stateful metadata uses `nativeSessionVersion: 2` and a `statefulProjection` version-one marker containing the ordered active row identities. Provider `ModelState` and `ModelHistoryCount` retain their native whole-session meaning. A completely acknowledged local history is cleared through a prepared journal receipt; archive rows remain available for audit and never supply a new append identity by tracking ID or snapshot comparison.

Restoration loads the complete archive to validate the confirmed frontier and reserve future numeric identities. Active rows must be a distinct, ordered suffix of that confirmed archive after provisional exclusions. Missing, unconfirmed, excluded, duplicated or unrelated IDs fail before live fields change. The final active history, provider acknowledgement cursor and pending interrupt ledger are validated together. A positive cursor must end at an assistant message and have provider state. Stateful histories use strict native validation rather than stateless indexed repair.

A fresh Agent restores the local active prefix together with its acknowledgement cursor. Its next model request includes only the unacknowledged suffix: for example, a tool result accepted after the server's function call. Successfully accepted tool bodies are not replayed by this restoration. Fully acknowledged history can restore as an empty active list even when the archive contains many earlier turns. The next row ID still comes from all archived rows, including unconfirmed rows.

Stateful and stateless metadata cannot silently exchange modes. Existing unversioned imported records and version-one stateless sessions retain their prior contract; they do not acquire stateful cursor semantics. Repository record bytes are native and are not interchangeable with Python session files.

Rows are written before metadata confirms their frontier, projection and provider state. Failed row or metadata writes keep stable live receipts for retry; success is marked only after the backend accepts the write. Cleanup preserves the first application/storage failure and attaches independent failures. A failure to prepare acknowledged-history clearing leaves history and cursor intact, and still runs `AfterInvocation`. Snapshot-to-record validation occurs before flushing pending rows.

This is not a transaction across repository records and the remote provider. A crash or persistent storage failure after a remote side effect can leave its outcome uncertain. There is no server receipt lookup, automatic remote replay guarantee, cross-process writer lease or active-body recovery. Applications serialize independent writers sharing an identity.

The pinned Python repository manager saves model state (`types/session.py:135–140,166–169`) but skips all local message restoration for a stateful model (`session/repository_session_manager.py:281–292`). TypeScript's snapshot manager similarly discards restored local history (`session/session-manager.ts:291–300`). Native cursor-aware restoration intentionally also preserves pending local outputs. No first-class context strategy transient state or complete arbitrary classic projection is serialized by this extension.

The dedicated tests exercise the native Responses provider over a real TCP HTTP/SSE fixture, fresh file-backed agents, human answers, abort retry, cancellation, early stream closure, malformed metadata and causal storage failures. They use no credentials or live provider service. Platform execution and package/API gates are recorded separately from these source contracts.
