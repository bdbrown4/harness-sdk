# Native telemetry

Automatic Agent invocation activities use accumulated lifetime model usage by default. The `gen_ai_use_latest_invocation_tokens` token in `OTEL_SEMCONV_STABILITY_OPT_IN` selects Python's latest-invocation alternative. The tracer snapshots this token at construction. This policy belongs to automatic Agent accounting; callers ending standalone span handles continue to supply their desired usage explicitly. See [automatic Agent telemetry](AGENT_TELEMETRY.md).

The telemetry increments provide `Strands.Agents.Telemetry.Tracer`, `TraceSpan` and `AgentTrace`: local execution traces, native .NET `ActivitySource` emission, message-content conventions and sensitive-attribute redaction. The [metrics collector](TELEMETRY_METRICS.md) adds detached local statistics and native .NET metric instruments. [Automatic agent integration](AGENT_TELEMETRY.md) connects ordinary calls and background tool bodies to those collectors. The optional [OpenTelemetry package](../src/Strands.Agents.OpenTelemetry/README.md) configures caller-owned tracing/metrics providers and official console/OTLP exporters. Harness telemetry configuration remains separate work.

The additive [provider timing contract](MODEL_TIMING.md) preserves reported latency and time-to-first-token values through model metadata and middleware, validates them before accepting usage, and maps native Bedrock stream latency without inventing missing measurements.

Create one tracer per agent. `StartAgentSpan` begins an invocation and resets its cycle collection. `StartAgentLoopSpan` adds a numbered root cycle; model and tool operations attach beneath that cycle. Each returned span owns its own local trace, so concurrent tool completions retain the correct tool-use identifier. `Tracer.Traces` contains cycles rather than the agent invocation itself. Local timing, metadata and optional immutable output messages are collected even when no listener/exporter exists. Collection and metadata getters return detached, read-only snapshots; trace objects remain explicitly mutable through their public methods. Completion is idempotent.

Applications subscribe to activity source `Strands.Agents` through their tracing provider. All operations use `ActivityKind.Internal`, matching the pinned SDKs. Agent spans inherit the caller's ambient context; cycles explicitly parent to the invocation, and model/tool spans explicitly parent to the cycle. Starting or ending an SDK span restores the caller's ambient activity. `WithContext` and `WithContextAsync` explicitly activate a span while application work runs, including across awaits, then restore the caller's activity and preserve application failures. `StartSpan` supports an explicit parent, detached roots and span links for work that outlives its originating invocation. These increments do not install a global tracing provider or exporter.

Activities include agent/model/tool correlation, start/end timestamps, stop reasons, token counters and exception status/events. Usage follows the pinned TypeScript `totalPromptTokens` rule: cache tokens are added only when the provider's explicit total shows they are not already included. Both legacy and current token attribute names are emitted; experimental conventions selected by `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` use `gen_ai.provider.name` and omit deprecated cache aliases. Tracer attributes are copied at construction, including array values; explicit operation attributes take precedence.

`RecordInput(ModelRequest)` records input messages and instructions. Legacy conventions emit per-message events; newer conventions use `gen_ai.input.messages`, `gen_ai.output.messages` and `gen_ai.system_instructions` with structured parts. `gen_ai_span_attributes_only` moves aggregated details into attributes, while legacy per-message events remain events. Langfuse endpoint detection selects aggregated attributes and marks agent spans as ordinary spans to prevent duplicate generation accounting. `gen_ai_tool_definitions` explicitly enables full tool schemas. Tool spans automatically record their input; `EndToolCall` records correlated text/rich results, omitting the dedicated success-result attribute for failed tools.

The default tool-span status follows TypeScript: an explicit exception marks failure. Construct `new Tracer(usePythonToolErrorStatus: true)` to select Python's result-status behavior as well. Without an exception, an error-status result uses its first text part as the status description, or `tool returned error status` when no text part exists; Python's empty-text case leaves status OK. This mode does not fabricate an exception or exception event. As in the pinned Python source, the derived error description is separate from the content-attribute allowlist. An explicitly supplied exception remains authoritative in either mode.

The Python content policy is opt-in through `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_unredacted_attributes=<names>`. Separate names with semicolons. Exact names and trailing-`*` prefixes are case-sensitive; a middle wildcard is a literal character. Omitting the token keeps content unredacted; an explicitly empty list redacts every protected field to `[REDACTED]`. Policy lookup always uses canonical names, including when legacy events physically use `content` or `message`. It covers input/output messages, system instructions, tool arguments and tool results. Redacted fields avoid serializing their private payload. Local trace output messages retain their immutable SDK values. Caller-supplied attributes and exception details are emitted as supplied.

Instrumentation failures cannot replace the application result or error. This includes failing activity start/stop listeners and context-change observers. Local completion and cursor cleanup still run. Error status and exception details are recorded before optional token arithmetic, so invalid token counts cannot hide the original application error. Content serialization failures cannot hide already-recorded status or prevent usage/span completion.

The behavior is grounded in pinned `strands-ts/src/telemetry/tracer.ts`, its local-trace tests and `strands-py/src/strands/telemetry/tracer.py`, with native concurrency/context isolation covered separately. The initial twelve-contract snapshot remains independently recorded in `TELEMETRY_LOCAL_SCOPE.json`. Later content/context contracts have separate evidence and require a new combined source freeze. Local Framework checks execute the `netstandard2.0` asset in actual x64/x86 processes; clean 4.8-only and current macOS verification remain pending. Typed system-content blocks, specialized memory/multi-agent instrumentation, latest-invocation token selection and the remaining telemetry families still require implementation and integration evidence.
