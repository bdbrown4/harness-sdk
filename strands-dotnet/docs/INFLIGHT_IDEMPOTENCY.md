# Inflight invocation joining

Set `InvocationOptions.IdempotencyToken` to join an invocation already running on the same Agent. Tokens compare as exact ordinal strings. Null disables joining; empty and whitespace strings are valid tokens. A later reuse after the inflight receipt clears starts a fresh invocation. This is not a durable response cache.

One primary owns initialization, input, model/tool execution, hooks, history and telemetry. A matching duplicate waits asynchronously and receives only the original terminal result or original failure. Its different prompt, invocation-state bag or scheduling options do not create a second execution. Its cancellation token cancels only that wait and does not cancel another waiter, the primary, or a caller-owned token source. Native Agent-global hooks run for the primary only; unlike Python's per-call callback handler, they are not replayed for duplicates.

Completion follows physical iterator disposal, final callbacks and existing cleanup. A terminal event alone is not a guarantee of successful cleanup. If a primary closes before yielding a terminal result without another failure, joined callers receive `IdempotencyAbortedException`; the primary's ordinary early Dispose need not throw that waiter-only error. A real cleanup failure takes precedence over this placeholder. Consumers must advance or dispose primary iterators; the SDK does not create a background event pump to rescue an abandoned iterator.

The receipt protects model-invocation admission only. Existing Shutdown, Dispose, Initialize, direct-call, snapshot, abort and classic-reduction guards remain authoritative. Some operations may be admitted after the original core clears `_invoking` while its final pending-provider report is still returning. The receipt never clears shared admission/cancellation fields again and does not lock future Agent history. An already joined caller observes its accepted prior result even if another admitted lifecycle operation follows; new calls on a disposed Agent still reject normally. Existing initialization failures remain memoized; token reuse does not reset initialization.

Structured duplicates use the already validated value captured through `IStructuredOutputTool.TryGetResult`, with no decoder/model/tool replay or retained decoder. The internal binding is attached before the existing final result hook so that hook, the primary and duplicates share the same final result and accepted value reference. Presence is separate from null. Compatibility follows CLR assignability: accepted null can match reference types and `Nullable<T>`, regardless of nullable reference annotations, but cannot match a nonnullable value type. Existing public `StructuredOutputTool<T>` null-deserialization rejection remains unchanged; the nullable interface contract is preserved rather than broadening that decoder policy. An incompatible or absent structured value fails only the requesting typed duplicate.

Pinned Python accepts any equatable, potentially unhashable token. Native strings avoid application `Equals` code under the admission gate. Pinned TypeScript has no equivalent inflight-token API. Native reentry detection covers propagated live invocation contexts and bounded synchronous prefixes; callbacks must not join their own primary. It does not claim universal detection of a cached self task, a stream consumer waiting on its own open iterator, later callbacks suppressing execution context, or unrelated suppressed background tasks. No thread receipt spans an await.

The expanded snapshot retains six runnable scaffold failures and all six minimum cases, then adds first-green coverage for simultaneous admissions, canceled primary/waiters, event isolation, exact tokens, late reuse, direct/session/interrupt/default paths, structured reference/null/type compatibility, initialization/final-hook/disposal failures, bounded reentry, and the closing-provider-report lifecycle gap. Final focused validation passed 868 cases across six Core/Compatibility runs on net8, net10 and installed Framework4.8.1 x64/x86, including 270 executions of these 45 cases. Normal Core package/API validation covered netstandard2.0, net8 and net10; four fresh NuGet-only consumers and four unchanged baseline-client binaries with matching new Core DLLs passed, including accepted structured reference identity. Nine owned C# paths passed positive whitespace probes, byte restoration and unqualified scoped formatting. Genuine Framework4.8 and full combined-platform validation remain separate integration work.

The closing-gap tests use the existing SDK logger isolation collection and restore its borrowed global logger in a finally block after physical joins. They demonstrate that an accepted Shutdown/Dispose waits for the original provider report, existing snapshot/direct/classic admission remains available, and an older receipt finalizer cannot release a later Abort's active admission. The receipt does not add new restrictions to these lifecycle APIs.

Cancellation keeps the existing distinction between the caller token exposed to invocation hooks and the effective token used by model I/O. The token option does not add a new linked source or take ownership of the caller's source. Structured interface-null tests use an explicit accepted-null interface implementation; they do not claim that the existing default structured decoder accepts null.
