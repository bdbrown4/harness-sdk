# Native Bedrock strict tools

`BedrockModelOptions.StrictTools` defaults to `false`. Enabling it sets each native tool specification's `strict` field to `true` and sends a transformed copy of its JSON input schema. Disabled mode leaves the native field unspecified and preserves the original schema. The same mapping serves ConverseStream, native Converse and subsequent configuration updates. It does not change the agent's local tool schema or make optional arguments required.

The transformation adds `additionalProperties: false` only to object schemas that lack an explicit value. It traverses `$defs`, `definitions`, `properties`, `items`, schema-valued `additionalProperties`, and `anyOf`/`allOf`/`oneOf`. A type array containing `object` receives the same closure. Literal `const`, `enum` and `examples` values are preserved as data, including exact 64-bit integers.

Pure `$ref` nodes remain references. A local reference with sibling fields is copied and inlined; the sibling fields override the target. Explicit `additionalProperties` values remain authoritative. Native JSON Pointer resolution decodes `~0`/`~1`, and chained aliases retain the final target's schema. These are deliberate correctness extensions beyond the pinned helpers' literal path splitting and single-reference merge. Recursive/external/unresolved references remain visible and generate a diagnostic when sibling inlining cannot complete. Original schemas are never mutated.

One private transformation helper owns schema copying, traversal, reference resolution and a depth/node budget; the request mapper owns native AWS fields and warning emission. This keeps provider adaptation separate from transformation without adding a public service hierarchy. The approach follows the proposal's [design principles](../../team/designs/0021-dotnet-sdk.md).

Strict transformation has a depth limit of 64 and a 100,000-node work budget. Exceeding either fails with `ModelException` before calling AWS. Invalid or duplicate JSON object properties fail with the same typed contract. The original schema and configured options remain unchanged. Bedrock remains responsible for deciding which schemas a selected model supports. Numeric/length bounds and explicit permissive `additionalProperties` are retained and reported by keyword; native warnings occur once per tool per request, rather than using TypeScript's global warning cache.

The selected recursive closure/merge behavior follows the TypeScript helper, whose ref-target precedence and object type arrays are more explicit than Python's helper. Bedrock does not apply Python's optional OpenAI-only `require_all_properties` behavior. `BedrockStrictSchemaTests` contains 15 contracts: six actual RED-to-GREEN cases (initial native mapping/closure/reference scenarios, alias/depth defects and typed duplicate-key failure) plus nine immediately green conformance cases. Full provider, modern/Framework and package results are recorded separately after verification.
