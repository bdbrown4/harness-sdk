# Model-backed extraction tracing

`ModelExtractor` observes its actual direct model stream. It does not construct an agent, add tools, retry the model, or contribute to an agent's cycle/token metrics. The extractor still borrows its explicitly configured model or the auxiliary/default model supplied by `ExtractionContext`.

`ExtractionContext.Tracer` is an optional borrowed tracer. The memory coordinator supplies its own tracer and source policy, so the chat activity belongs to the active `memory.extract` root. The optional `ModelExtractorOptions.TelemetryProfile` overrides the manager's policy; an omitted policy defaults to TypeScript for standalone calls. Existing constructors remain available.

The default TypeScript profile traces only when a context tracer is supplied. Its chat activity inherits the extraction activity as parent without making the chat activity ambient during provider calls. The Python profile also traces standalone extraction and makes the chat activity ambient for stream construction, reads, and iterator cleanup. Both restore the caller's ambient context. Empty batches and pre-canceled calls create no model activity.

The activity records the chosen model's optional identity, the rendered role-labeled transcript, system instructions, output, and stop reason. These are model content and follow existing model-content redaction and event/attribute conventions; they do not use the verbatim memory query/result payload policy. Model identity observation and failing activity listeners cannot prevent extraction.

TypeScript preserves absent provider usage and emits positive latency in milliseconds only when usage was reported. Python's pinned streaming helper initializes zero counters for a completed call, even if its provider emitted no usage. The explicit Python extractor profile reproduces that trace accounting and records positive latency and time-to-first-token in milliseconds. Those zeros are compatibility accounting, not measured provider usage. The SDK accumulator's `UsageReported` semantics and the agent's metrics remain unchanged. Propagation-only activities are stopped without fabricating result accounting or success status.

The chat activity finishes before tolerant fact parsing. Malformed fact JSON still produces an empty fact list and a successful model activity after a valid response. Missing terminal responses and model failures remain errors. Iterator cleanup is attempted, and original provider failures retain cleanup diagnostics. Requested caller cancellation wins over a backend failure observed after cancellation, preserving that failure as the cause and retaining the caller's token. Cancellation accepted during cleanup, activity completion, or parsing prevents a successful fact return. Cancellation after model-span completion preserves that successful span status. The extractor does not dispose the borrowed model or tracer.
