# Bedrock cache profiles

`BedrockModelOptions.Cache` is optional. Its default `null` retains the existing `CacheSystemPrompt`, `CacheTools`, `CacheLastMessage` and `CacheTtl` behavior. Supplying a `BedrockCacheOptions` makes that profile authoritative for the three managed sections; each section defaults to enabled. It does not change the borrowed AWS client's credentials, endpoint, retry configuration or ownership.

`Auto` recognizes the exact case-sensitive substrings `anthropic` and `claude`, matching the pinned TypeScript provider. `Anthropic` enables the profile for an opaque model identifier. `AutoIgnoreCase` is an additional native alternative which folds ASCII A–Z only. It does not promise Python's arbitrary Unicode `lower()` behavior; dotted I, dotless I and lookalike Cyrillic letters inside a family name do not become ASCII letters.

Each section has an optional TTL and falls back to the shared TTL when its value is empty or absent. Nonempty strings remain open vendor values: the service validates them. No local duration allowlist, trimming, ordering repair or minimum duration is introduced. A system TTL inherited from the shared value is omitted when an actual tools checkpoint has a different TTL. An explicitly supplied system TTL, including an empty string that falls back to the shared value, bypasses this standdown. Missing tools do not force standdown.

Managed system caching supports the legacy string prompt and detached typed system blocks. Caller checkpoints retain their order and TTL authority, and managed caching does not append a duplicate point. The explicit profile can fill an absent caller TTL using its system setting and tools standdown rule; see [structured ordinary system prompts](BEDROCK_SYSTEM_PROMPTS.md). An empty legacy string retains its ordinary text representation. Explicit tool-choice `None` continues to suppress tool definitions and the history compatibility tool.

Message caching reuses the existing native boundary policy: final user selection, first explicit boundary, duplicate cleanup, dynamic trailing content and non-PDF document placement. Disabling the message section, or selecting an unsupported automatic model, preserves caller checkpoints without rewriting their TTLs. Input message objects remain unchanged. Configuration records returned by `GetConfig` are detached, and an admitted request keeps its accepted model/profile while a later `UpdateConfig` affects future requests. Invalid strategies fail before publication.

The Python and TypeScript public configuration objects differ. Python lowercases automatic family matching, defaults its tools setting through a deprecated flag, lacks the separate message-TTL field, and treats explicit empty section TTLs differently. Native explicit section booleans and per-section values can express the relevant wire choices; this is not a claim of interchangeable source configuration DTOs. `Cache = null` is the native compatibility default rather than a claim that upstream defaults are identical.

The scoped conformance tests use the official AWS SDK against signed loopback requests for stream acquisition, ordinary Converse and CountTokens. They cover open TTL values, model-family/Unicode boundaries, section absence, existing placement rules, accepted configuration snapshots, service rejection, borrowed-client reuse, caller cancellation and composition with recovery/reasoning/Nova mapping. CountTokens applies accepted formatting only. The cache profile does not add parser retries or change event replay, managed-field authority, remote validation errors or existing cancellation behavior. Local token estimation continues to avoid transport work.

The source behavior is pinned to commit `3bd98e618320f0f286acbfb2252f72388030421b`. Package/API, installed Framework 4.8.1, genuine Framework 4.8 and complete combined-platform acceptance are separate evidence boundaries; a selected component gate does not establish the others.
