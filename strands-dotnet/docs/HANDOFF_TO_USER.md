# Optional handoff-to-user tool

`Strands.Agents.VendedTools.HandoffToUser.Create()` returns an `IRichTool` that uses the existing human-interrupt lifecycle. Add it explicitly to `AgentOptions.Tools`; it is not an implicit Harness default. Construction performs no I/O and owns no UI, transport, callback registry, or wait loop.

`HandoffToUserOptions` selects the tool name, description, and `Behavior` (`TypeScript` by default or `Python`). The model-facing input is an object containing a required nonblank `message` string. The valid string is retained verbatim as the interrupt reason. Renaming the tool never changes its fixed `strands:handoff-to-user` interrupt name. The two profiles use their pinned JavaScript `trim`/Python `strip` whitespace sets, which differ for U+FEFF, U+0085, and U+001C–U+001F.

The agent returns `StopReasons.Interrupt` and its interrupt descriptors when a response is missing. Resume with no new prompt and an `InvokeOptions.InterruptResponses` entry containing the returned descriptor ID and a detached JSON response. Explicit JSON null is an answer. The framework retains completed sibling results and accepted answers across pause, session persistence, and fresh-agent restore; the helper neither acknowledges provider history nor changes tool replay policy. Place application side effects after approvals when writing other interruptible tools.

The profiles preserve different reply layouts:

- TypeScript maps null, strings, numbers, and booleans to text. An exactly recognized `text`, `json`, `image`, `video`, or `document` object becomes typed content. A nonempty array consisting entirely of recognized content becomes ordered blocks. Other objects become one `JsonBlock`; other arrays become one `JsonBlock` containing `{ "$value": originalArray }`.
- Python maps ordinary nonstring replies to JSON text. An object containing both `status` and `content` is a result envelope: the native profile requires `success`/`error` and a fully representable content array, and always correlates the result with the current tool-use ID. Additional outer keys are retained together in the existing detached `ToolResultBlock.Metadata` object; an outer `metadata` key remains nested there. This is a native typed layout rather than the foreign dictionary wire schema. Metadata is persisted locally and excluded from provider payloads.

Outer keys such as `structuredContent` or `_meta` remain opaque metadata members. They do not automatically set the native `StructuredContent` property or acquire MCP/provider semantics. Duplicate extra-key names are rejected before result publication; known-field lookup uses the native JSON DOM's last property value. This documents the native raw-JSON boundary rather than claiming foreign dictionaries can carry duplicate keys.

Typed media supports serialized base64 bytes and S3 references, HTTP(S) image references, and document text or ordered text segments. Document name, context, and `citations.enabled` are retained. References are never fetched. Existing native S3, HTTP(S), and single-source validation applies. Unknown fields, ambiguous sources, malformed bytes, unsupported formats, or nullable fields that cannot be represented without losing information do not silently disappear: TypeScript falls back to the whole original JSON value, while a claimed Python result envelope is rejected as a whole. This lossless native profile is stricter than permissive foreign constructors or untyped dictionaries. It does not claim support for foreign live class instances, Python BaseModel objects, or cycles, which cannot be carried by a detached `JsonElement` answer.

Python envelopes set `ToolResultBlock.HasExplicitContent`, so an empty content list remains distinguishable from legacy text fallback. The new property defaults to false and is omitted from serialized JSON when false. Existing text/rich constructors, deconstruction, and missing-field legacy payloads retain their earlier behavior. The explicit intent survives native message copying, indexed repository records, whole snapshots, and immutable catalog checkpoints. Anthropic respects the explicit empty list; provider-specific projection differences elsewhere remain separate contracts. In particular, this helper does not establish universal empty-result or media support across model providers.

Use `IRichTool.InvokeResultAsync` for direct access to blocks, status, metadata, and explicit-empty intent. The inherited `InvokeAsync` is the textual convenience projection and does not flatten rich media into a universal string format. Before interrupt dispatch, cancellation is attributed to the original operation token or the context's captured execution signal, with operation-token precedence if both are already canceled. A synchronous accepted answer is not relabeled as uncommitted merely because cancellation races inside its callback. Broader invocation cancellation remains owned by the agent.

Native numeric/JSON spelling, URI representation, and base64 normalization are distinct from JSON value and content-layout parity. No byte-for-byte JavaScript/Python formatting equivalence is claimed.
