# Remaining logging call-site integration

This separate increment depends on the immutable logging20 facade and the exact `36341c79f5e604e85b4d1382a521bdb49d5734fb` source. It migrates the remaining unowned native diagnostics in Agent tool/continuation partials, first-class Context helpers, the core Llama API adapter, and Bedrock, SageMaker, Monty, and bidirectional packages. It changes no context-reduction algorithm, session format, tool registry, provider protocol, ownership policy, or public API.

Each existing message body and control-flow catch is retained. Original exceptions are passed to the standard logger where the diagnostic has one. Logger failures remain observational under the previously reviewed native facade contract; host callbacks do not replace accepted results or original operation errors. The former context-summary `Trace.WriteLine` message is routed at Information level, retains its body, and remains Trace-only with the default logger. The default Trace event prefix follows the standard logger bridge. [LOGGING.md](LOGGING.md) documents borrowed logger/factory ownership and independent SDK/harness configuration.

Internal helpers carry the actual summary failure and return observer failures to the two existing Bedrock/Bidi diagnostic journals without expanding the public API. Their original guarded append/replace policy and exact secondary exception identities are retained; other diagnostics remain observational. An existing Bedrock listener regression exposed this required distinction before the final gate. One Core `InternalsVisibleTo` entry permits the Monty package to use the same internal dispatcher as the existing optional-package friends. The isolated project variants contain only that entry and the exact Bedrock logging-test compatibility link; compose these additions into shared projects instead of replacing moving project files.

Thirteen tests first failed against real diagnostic paths, then passed after routing them to the configured host: context filter and summary, continuation callback, nested Agent pause, Llama request formatting, actual AWS request fixtures, bidirectional snapshot trigger/save, and Monty alias construction before worker admission. Optional-package theories include throwing loggers. The Monty logging tests cancel in the host callback before admitting a worker; genuine worker execution is covered separately by the existing Monty regression suite and its physical architecture assertions.

MCP diagnostic migration was separate from this frozen thirteen-contract increment; the subsequent [MCP logging17 scope](MCP_LOGGING.md) completes its identified warning branches without changing transport lifetime. Native package-consumer stdout is operational verification output, not a diagnostic, and the default dispatcher's Trace/console bridge must remain. Classic conversation reducers contain no remaining diagnostic calls and are not prerequisites of this capsule. The inventory JSON lists the exact prior calls and remaining owner boundaries. This increment does not claim full SDK parity, current macOS validation, or complete five-RID Monty/Harness release packaging.
