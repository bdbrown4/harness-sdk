# MCP tool-change subscriptions

`McpClient.WatchToolChangesAsync` owns an independently filtered discovery cache and a borrowed asynchronous callback. `Current` starts at version 0 after the complete initial discovery. Each accepted refresh increments the version and includes the previous adapted names and complete new tools. The membership collections are detached and read-only; each returned tool retains its accepted output-schema binding. Later discovery does not change an older tool's validation.

The default Python profile waits 300 milliseconds for each serialized round and keeps a coalesced trailing round after a refresh or callback failure. The explicit TypeScript profile waits for a quiet debounce period and drops an already queued round after a failed round. Both commit the complete cache before calling the observer, retain that cache if the observer fails, and can process future notifications. Separate subscriptions have their own prefix, filter, bounds and callbacks. Borrowed delegates run outside native state gates.

MCP 2026-07-28 starts one shared `subscriptions/listen` request for the native subscriptions. Acknowledgement must grant `toolsListChanged` and carry the exact typed listen request ID in `io.modelcontextprotocol/subscriptionId`. Foreign IDs cannot authorize or refresh a native subscription. A forwarding reader observes wire order before the official SDK schedules notification handlers, so a real wire change before acknowledgement fails, while valid acknowledgement followed immediately by change survives callback reordering. This uses the public transport reader and the existing official pump. Legacy negotiated protocols observe the untagged push notification through that same pump and send no listen request.

Creation cancellation removes only that observer. Disposing the last subscription or the client cancels and physically joins admitted initial discovery, refresh/filter/callback work and the listen request. A failing watcher never disposes the shared client. A fresh watch after the failed generation is closed is an explicit new generation; automatic reconnection is not provided. `Completion` reports terminal listen/session loss. Refresh and observer failures are diagnostic and retain the accepted cache.

Callbacks must cooperate with their lifetime token. A worker cannot enter its own client's watch/client lifecycle or join any watcher on that shared client, because a shared close may be joining all workers. Receipts cover filters and synchronous diagnostic callbacks as well as the observer. They expire before physical drain. During synchronous cancellation delivery, captured contexts for the canceled watcher are conservatively rejected even if their original worker receipt has expired; ordinary escaped contexts are independent after cancellation delivery ends. A cached raw `Completion` task can still be awaited from a callback, so universal self-wait detection is not promised. Unrelated posts from an `IProgress` implementation are not joined.

`McpToolProviderOptions.ToolChanges` opts a provider generation into this cache. Null preserves its original one-time cached discovery. `OnToolsChanged` requires opt-in and runs after the provider cache commits. Higher snapshot versions win over a racing initial load. Following terminal subscription completion, later loads throw its retained cause until all consumers leave and a new generation is admitted. Removal also retains terminal/cleanup failures while attempting client cleanup. Host HTTP clients, callbacks and consuming agents remain borrowed. This does not live-publish tools into an already initialized Agent, change `IToolProvider`, or implement managed reload.

The scheduling profiles follow the pinned TypeScript client and Python MCP client. Native multiple subscriptions, strict acknowledgement validation, bounded discovery and lifecycle receipts are explicit native contracts. The official `Protocol` property remains application authority; unrelated application-created protocol subscriptions are independent.

An earlier design proposed one refresh lock per client. The implemented native extension instead serializes rounds within each subscription, allowing a blocked borrowed observer in one independently filtered scope to coexist with progress in another. The upstream scheduling comparison applies to one watcher at a time, and does not claim upstream multiple-watcher equivalence. Complete accepted metadata still commits through the existing native discovery gate.

The provider applies the same conservative cancellation-delivery guard to connector/load contexts, including the default provider without notification opt-in. A captured callback cannot synchronously join its own generation close while its lifetime token is delivering cancellation. This does not promise to distinguish an unrelated escaped task carrying the same captured context during that delivery window.
