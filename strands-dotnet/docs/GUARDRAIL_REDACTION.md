# Native guardrail redaction

The pinned TypeScript model and agent contracts define provider redaction events, assistant replacement, and input-history replacement. Native `ModelRedactionEvent` supplies optional `InputReplacement` and `OutputReplacement`; at least one must be supplied. An empty replacement deliberately erases text. Events require a message start and may arrive after message stop/usage. Repeated redaction of the same direction is a protocol failure. Other content remains forbidden after stop.

The accumulator replaces complete assistant content while retaining response metadata and usage. It rejects an output replacement that would erase emitted tool-call correlation. An input replacement retains the latest user message's tracking ID. Ordinary input becomes one text block; a tool-result message retains only its result IDs/statuses and replacement text, discarding other content, structured results, error objects and message metadata. Input source objects remain unchanged.

`AgentOptions.InputRedactionTiming` chooses between the meaningful upstream behaviors. The default `AcceptedTurn` applies input redaction only after the provider stream and its cleanup complete, middleware accepts its result, and the after-model hook accepts the turn. Discarded middleware attempts, cached replacements, retry requests, failed/incomplete streams and early consumer disposal do not commit that attempt's redaction. `InvokeModelResult.InputRedaction` explicitly carries the accepted policy across middleware transformations. `ProviderEvent` applies provider input redaction before exposing its event to stream consumers, including when the provider later fails, middleware discards that attempt, or the consumer stops early. Already applied redaction is retained on retry. The accepted result does not repeat that inline commit.

In either mode, session-backed agents save the redacted projection before publishing it in memory, so a failed save does not partially rewrite history or append the assistant. Once storage accepts the projection, the memory commit completes even if caller cancellation races it. A later assistant-save failure leaves the accepted redaction in place. A last message with an assistant role is left unchanged.

`AcceptedTurn` follows the TypeScript model/agent separation. `ProviderEvent` follows Python's inline input-redaction timing. Redaction cannot retract earlier stream deltas, caller-owned input, application logs, previous snapshots, or provider-side history. The optional `RedactedOutput` field carries original trace content when the provider supplies it and output redaction is enabled.

## Bedrock configuration

`BedrockGuardrailOptions` adds `RedactInput` (default `true`), `RedactOutput` (default `false`), `InputReplacement` (default `[User input redacted.]`) and `OutputReplacement` (default `[Assistant output redacted.]`). Replacement strings cannot be null. Configuration publication validates before replacing the current immutable options. Guardrail request selection and guard-content wrapping retain their existing configuration.

Both native Converse and ConverseStream assess the official AWS trace unions for content, topic, custom/managed words, PII, regex and contextual-grounding policies. SDK redaction requires an assessment with `action=BLOCKED` and `detected=true`. A present guardrail trace is authoritative, even when empty: `ANONYMIZED` masking and undetected policies do not trigger SDK replacement. Only an absent guardrail trace permits fallback from `guardrail_intervened`; a stream without metadata uses the same fallback at successful completion. Unconfigured guardrails and explicitly disabled input/output redaction do not emit replacement events. Native Converse uses the same parser and supports trace responses without usage.

## Evidence and boundaries

`ModelRedactionTests` covers 20 contracts, including detached history/session reload, correlated rich results, authoritative middleware retries/cache, after-hook retry, early disposal, save failure and the two timing policies. `BedrockGuardrailTests` covers 20 contracts through the official AWS response/event unmarshalling path and real native Agent loop. The first six core, six provider and four timing scenarios each had an executable RED before implementation and GREEN afterward; the remaining cases are conformance/regression evidence. This is a bounded guardrail contract, not complete Bedrock or event parity. Current full-matrix results are recorded separately in `VALIDATION_RESULTS.md`.
