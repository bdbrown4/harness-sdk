# Native S3 byte storage

`Strands.Agents.S3` exposes `S3Storage`, `S3StorageOptions`, and `S3MissingKeyPolicy` over the existing four-operation `IStorage` and native search interfaces. Agent, Harness, memory defaults, and session repositories are unchanged. Knowledge bases, embeddings, QMD, and BM25 are separate capabilities.

Use `new S3Storage(client, bucket, options)` with a borrowed official `IAmazonS3`, or `new S3Storage(bucket, options)` for a lazy owned client. `Region` is available only with the owned constructor. Supplied clients are never modified or disposed. Options are immutable records; writes copy caller bytes synchronously before their first await and reads return independent buffers. Unused construction/disposal does not resolve clients or credentials.

## Package and source profile

The selected `AWSSDK.S3` pin is 4.0.104.5. The official NuGet package provides `netstandard2.0`, `net472`, `netcoreapp3.1`, and `net8.0` assemblies, and requires `AWSSDK.Core` in `[4.0.102.12, 5.0.0)`, matching the existing optional Bedrock/SageMaker floors. This is a verified explicit pin, not an evergreen latest-version claim.

Behavior is based on pinned Strands revision `3bd98e618320f0f286acbfb2252f72388030421b`: TypeScript `src/storage/s3-storage.ts` and Python `src/strands/storage/s3_storage.py`, plus their tests. Native calls use official PutObject, GetObject, DeleteObject, and ListObjectsV2 APIs. There is no foreign runtime or public transport wrapper.

The default exact `NoSuchKey`/`NotFound` missing-read profile matches TypeScript. `NoSuchKeyOnly` matches Python. `NoSuchBucket`, `AccessDenied`, differently cased codes, and unclassified HTTP 404 retain their native cause in a `StorageException`. Missing deletes use S3's native idempotent delete; bucket/permission errors are not suppressed.

The existing internal `StorageKey` rules collapse repeated slashes and reject backslashes, empty value keys, and literal `..` segments. A base prefix has one separating slash, explicitly avoiding Python's possible doubled separator after a configured trailing slash. Query prefixes preserve a meaningful trailing slash. Full view-relative keys are sorted ordinally. A physical bucket/base prefix does not claim `IsNamespaced`; existing borrowed `Namespace` views are logical views, not IAM access confinement.

Each listing requests `MaxKeys=1000` without a delimiter. Opaque continuation tokens pass unchanged. Truncated pages require a nonempty, previously unseen token; missing/repeated/cyclic tokens and out-of-query-prefix keys cause a protocol failure before publication. Every relative result must also be a nonempty canonical native key, exactly equal to `StorageKey.Normalize(relative)`. Foreign doubled/leading/trailing slash aliases, backslashes, and `..` segments are rejected as a whole result, so a returned key cannot silently read another object after native normalization. Ordinary slash-separated segments remain valid and percent-encoded-looking strings are opaque literal keys, never URL-decoded. Nullable SDK-v4 object lists are empty. These finite-progress/authority/canonicality checks are native correctness extensions.

## Search and accepted writes

The borrowed existing `StorageSearchStrategy` defaults to `KeywordSearchStrategy`: distinct query words found in key/UTF-8 content, descending score then ordinal key. Indexing follows successful Put and gets a separate byte copy. Index failure therefore can mean the object was already written; it does not undo or replay Put. Native namespace search can scan the underlying store before filtering.

## Cancellation and ownership

Caller tokens are borrowed. Requested caller cancellation surfaces the caller's exact token, retaining a mismatched backend failure as its cause. A matching cancellation exception retains its identity and original throw-site stack; independent backend cancellation stays independent and also preserves its stack. Accepted SDK, response-copy, and strategy work is physically joined even if it ignores cancellation. An accepted remote write may coexist with later cancellation/index failure; no transaction, automatic replay, or exactly-once remote effect is claimed.

Disposal prepublishes one completion before callbacks, closes new admission, signals only the store's lifetime, joins accepted work, then disposes a created owned client. Callback self-disposal fails fast; escaped completed callbacks cannot reopen admission. Synchronous disposal has the same physical join and requires cooperative backend completion. Owned `GetObjectResponse` bodies are disposed once. Primary failures retain independent cleanup errors under `Strands.CleanupErrors`, excluding self references and duplicate references.

A successful response without a body is a native protocol failure, unlike TypeScript's missing-value fallback. No arbitrary object-size cap is added; native byte-array/stream limits apply. AWS SDK signing/retry/checksum/credential behavior is retained. Owned-client application/user-agent identifiers remain under SDK defaults; no equivalent to Python's `strands-agents` suffix is claimed. No live AWS, IAM, credential, large-object, or remote durability proof exists.
